# 安全工程规范

适用于所有项目,与技术栈无关。按以下规范行事:

## 密钥与配置

- 绝不把密钥/令牌/密码硬编码进源码或提交进 git;一律用环境变量或 secrets 管理器
- 含密钥的本地文件(`.env` 等)必须进 `.gitignore`;仓库只保留 `.env.example` 模板
- 密钥一旦进入 git 历史,立即吊销并轮换——仅删除文件无法清除历史

## 注入与输入

- 所有外部输入都不可信:参数化查询(不拼接 SQL)、转义输出(防 XSS)、校验并约束入参
- 不对未校验输入执行 `eval`、命令拼接或不安全的反序列化
- 文件路径、URL、命令参数等来自外部时,先做白名单/规范化校验

## 依赖与供应链

- 定期做依赖漏洞审计:`npm audit` / `pip-audit` / `cargo audit` / `govulncheck`
- 锁定依赖版本;引入新依赖前核查来源、维护状态与许可证

## 默认安全

- 最小权限:文件、网络、密钥访问按需授权,不用通配权限
- 日志与错误信息不泄露密钥、内部栈细节或用户隐私数据
